Rules are a list you order, and deep links are something you can read

The first rule that matches now wins, so the order of the list is what decides. New rules are placed narrowest first, so a broad one added later does not quietly shadow a narrow one that was already there — and the arrows under the table are how you overrule that when you want to.

The nine app handoffs are ordinary rules now. They used to be checkboxes, which said the list of apps was nine long. Each one is a line in the table you can read, move, edit or delete, and writing your own takes nothing special:

app:bear://{rest}    link    bear.app/{rest...}

Deep links are a pattern and a template. zoom.us/j/{id} becomes zoommtg://{host}/join?confno={id}, written in the rules file rather than compiled into the app. The vocabulary is four things: {name} for one path segment, {name...} for the rest of the url, {host} for the host that matched, and ?key={name} for a query parameter found wherever it actually appears. A pattern that does not match is an app declining the link, so zoom.us/pricing goes to a browser without anything being written to say so.

  • Rules can be edited, not only added and deleted.
  • Presets moved into the add button, next to “New rule…”.
  • BrowserRouter --save rewrites the rules file in the current format.
  • The rules file documents the whole vocabulary, so anything that can write a line of text can add a rule.
